# Content-Addressed Dependency Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Persist package-manager caches BETWEEN tasks so a repo's setup phase (`npm ci`, `go mod download`) reuses previously-fetched packages instead of re-downloading every task. Content-addressed, keyed so identical inputs hit the same warm cache; **RW to the trusted setup VM, READ-ONLY to the agent VM**; no cross-repo sharing; fail-closed. The one narrow, documented exception to A7 — host-managed, content-addressed, trusted-setup-produced, agent-read-only — with a redteam test.

**Architecture:** Opt-in per repo (`profiles.repos[key].cache: true`). Before setup, the broker hashes the repo's lockfiles host-side (fail closed with NO cache if a repo has only a manifest, no lockfile) into a cache key = `sha256(repokey + sorted-lockfile-digests + toolchain/arch + setup-command-digest + image-ref)`. The cache dir for that key is mounted **rw into the setup VM** and **ro into the agent VM** (Apple `container --mount ...,readonly` presence flag), with tool cache env (`npm_config_cache`/`GOMODCACHE`/`PIP_CACHE_DIR`/`CARGO_HOME`) pointed at it in both. Only tool *payload* caches live there — auth/config stays in the ephemeral `HOME`, never cached. An LRU + size-cap + host-free-floor eviction bounds the store.

**Tech Stack:** Go stdlib, Apple `container` CLI, the sandbox image.

## Decision record (locked — from the security analysis)

- **No cross-repo dedup.** The cache key includes `repokey.Normalize(repoRef)`, so two different repos with identical lockfiles get DIFFERENT keys and never share a cache dir → a malicious repo's setup can never poison another repo's cache. Within a repo, same key = same inputs = correct reuse (the operator opted this repo into caching its own setup output).
- **RW to setup, RO to agent.** The setup VM (bearer-free, squid-only, host-config commands) populates the cache; the agent VM only reads it (readonly mount). The agent can never write cross-task state — A7's spirit holds (agent-writable state still doesn't persist).
- **Payload caches only, never auth.** Point `npm_config_cache`/`GOMODCACHE`/`PIP_CACHE_DIR`/`CARGO_HOME` (registry-payload caches) at the cache dir; leave `HOME`-level tool config (`.npmrc`, `.netrc`) in the ephemeral VM `HOME` so registry tokens never land in the persistent cache.
- **Fail closed on mutable inputs.** The key must be pinned by a lockfile (`go.sum`, `package-lock.json`, …). If a repo has only a manifest (`go.mod`, `package.json`) and no lockfile, caching is DISABLED for that task (a warm cache would serve deps for an under-pinned key). Warm cache is best-effort: a miss just re-fetches through squid — the cache is a speedup, never a correctness dependency.
- **Bounded.** A `CacheQuotaGB` cap (default e.g. 20) with LRU eviction by access time + a host-free-space floor (reuse the `freeBytes` guard). The cache can never fill the disk (A8 extended to a persistent store).
- Cache key + hit/miss recorded in the brief's `SetupEvidence` (broker-observed).

## Global Constraints

- Lockfiles hashed host-side with the `O_NOFOLLOW` sha256 idiom (`fileSHA256NoFollow`) from the untrusted `/work` clone, BEFORE setup runs (so a setup command rewriting a lockfile mid-run can't cause a key/content mismatch — same class as the prompt-tamper defense).
- The agent VM's cache mount MUST be `readonly`; the setup VM's rw. Assert both in the runner argv tests.
- `CacheRoot` dir is `0700` (like the other state dirs), added to `expandHome` + the env-override block + a new default under `~/.drydock/cache`.
- No secret/proxy material baked into cached files; the cache stores only tool-payload subpaths.
- A7 sub-clause added to `THREAT_MODEL.md` + a VM-backed redteam test (agent can't write the RO cache; distinct keys don't collide) wired into `make redteam-vm`.
- Go gate before each commit: `go vet ./...`, `go test -race ./...` (scope per task), `gofmt -l internal/ cmd/` silent, `staticcheck ./...` clean.

### Task 2: `internal/depcache` — key + CAS store + eviction

**Files:** Create `internal/depcache/depcache.go` + `_test.go`.

**Interfaces (pure/host-side; no container):**
- `type Key struct { RepoKey string; LockDigests []string; Toolchain, Arch string; SetupCmdDigest, ImageRef string }`
- `func ComputeKey(k Key) (string, error)` — canonical, injective encoding (mirror `explain.go`'s `profilesHash`/`globsHash`: sorted lock digests via a `globsHash`-style combine, `quoteArgv`-style for any list, all fields length-prefixed/quoted so boundaries can't collide), sha256 hex. Error if `RepoKey==""` or `len(LockDigests)==0` (no lockfile → no cache — the fail-closed rule enforced at the key layer).
- `type Store struct { Root string; QuotaBytes int64 }`
- `func (s *Store) Dir(key string) (string, error)` — returns `<Root>/<key>`, creating it 0700 on first use; touches an access-time marker; refuses a key that isn't 64 hex (traversal guard).
- `func (s *Store) Evict(minFreeBytes int64) (freed int64, err error)` — LRU by the per-entry access marker: while total-cache-bytes > QuotaBytes OR host-free < minFreeBytes, remove the least-recently-accessed entry dir (root-shape guarded RemoveAll). Reuse a `freeBytes`-style statfs (import or replicate the small helper).
- `func LockfileDigests(workDir string) ([]string, bool)` — walk the repo work tree for known lockfile filenames (reuse the `trustbrief` `FlagLockfile` list — export a `trustbrief.LockfileNames()` or a small shared list), hash each with an `O_NOFOLLOW` sha256 (refuse symlinks), sorted `name:digest` strings; returns (digests, hasLockfile). No manifest-only fallback here — the caller disables cache when `!hasLockfile`.

- [ ] **Step 1: Failing tests** — `depcache_test.go`:
  - `TestComputeKey_StableAndInjective` — same inputs → same key; a change to ANY field (repokey, a lock digest, toolchain, arch, setup-cmd, image) → different key; reordering lock digests → same key (sorted); `[]LockDigests{}` → error; a lock digest that's a substring boundary of another can't collide (injective encoding).
  - `TestStore_DirCreatesAndRejectsTraversal` — `Dir("ab..")`/non-hex → error; a valid 64-hex key → dir created 0700.
  - `TestStore_EvictLRU` — populate 3 entries with staggered access markers, set a tiny QuotaBytes → the least-recently-accessed dirs removed first until under quota; root-shape guard (refuse empty/`/`).
  - `TestLockfileDigests` — a temp repo with `go.sum` + `package-lock.json` → 2 sorted digests, hasLockfile true; a repo with only `go.mod` → hasLockfile false; a symlinked lockfile → refused (not hashed).

### Task 4: broker — wire the cache

**Files:** Modify `internal/broker/setup.go` (compute key, resolve dir, pass to setup, record hit/miss), `internal/broker/broker.go` (Cache config fields, agent VM cache mount + env, eviction), `internal/trustbrief/brief.go` (`SetupEvidence.Cache` — key/hit fields), `cmd/brokerd/main.go` (wire CacheRoot/CacheQuotaGB + a boot/periodic eviction); tests.

**Behavior:**
- `Broker` gains `CacheRoot string`, `CacheQuotaBytes int64`, and the per-repo cache flag comes from the `SetupProfile.Cache` already in `b.Setup`. Wired from config in brokerd.
- In `runSetup` (before running setup commands), when `b.CacheRoot != "" && cfg.Cache && b.CacheQuotaBytes > 0`:
  - `digests, ok := depcache.LockfileDigests(tr.st.WorkDir())`; if `!ok` → NO cache (leave CacheDir empty; record `SetupEvidence.Cache = "disabled: no lockfile"`).
  - else compute the key (repokey + digests + arch(runtime.GOARCH) + setup-command-digest(a profilesHash-style digest of cfg.Setup+Readiness) + b.ImageRef + a toolchain marker); `dir, _ := store.Dir(key)`; a "hit" = the dir already had payload (non-empty) before this run.
  - pass `dir` as the setup VM's rw CacheDir + inject `runner.CacheEnv()` into the setup env; record `SetupEvidence.Cache` = `{Key: key[:12], Hit: bool, Path: <dir>}`.
- The AGENT VM: thread the same cache `dir` into `runner.Spec.CacheDir` (RO mount) + `runner.CacheEnv()` into the agent env — but ONLY when caching was active for this task (dir set). (So the agent reads the warm cache the setup just populated.)
- Eviction: after setup populates (or at brokerd boot + periodically), call `store.Evict(minFree)` guarded. Simplest for the MVP: evict once after each cache-using task's setup completes (bounded, amortized) + a boot sweep. Keep it off the task's critical path if slow (a goroutine is fine, but ensure no race on the entry being read by the live agent — evict only entries NOT currently in use; simplest safe rule: eviction runs at boot and after task completion, never mid-task on the active key).
- `SetupEvidence.Cache` struct in trustbrief: `{ Status string; Key string; Hit bool }` (json omitempty) — broker-observed.
